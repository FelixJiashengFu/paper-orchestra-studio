# PaperOrchestra Studio

Use the plugin's PaperOrchestra Studio MCP tools. It connects to the user's local Studio installation and shares its projects, runs, preferences, providers and library. Use `studio_status` for a connection problem and `open_studio` when the user wants the desktop interface.

- **Manuscripts.** Use `list_projects` and `get_project` to identify the project. Use `check_environment` for template IDs and model routing. For a new project, create it, then use `update_project` with the returned `updatedAt` and the fields the user wants. Use `parse_intake_form` to read a manuscript intake document. A writing run needs the user's actual research idea and experimental record. Pass the chosen project to `start_run`. Use `list_runs` and `get_run_logs` to track it, and `get_run_artifacts_summary` to locate the results.
- **Research.** Use `run_sop_workflow` for paper reading, literature review, topic ideation, reproduction and mathematical modeling. Supply user-provided local files and notes in `payload`. Use `run_data_profile` or `run_data_analysis` for data. Studio may add saved library records and writing preferences to the SOP context. Use `queryOnline: false` in the SOP payload when the user wants to skip online literature retrieval. Model inference still follows Studio's provider configuration.
- **Literature and figures.** Use the literature tools to search, resolve DOI or PDF metadata, save reviewed items, build graphs, or export citations. Figure tools work with Studio's existing versions. Use normalized top-left coordinates for partial revision. Open the Studio tab for drag selection and visual comparison.
- **Editing and submission.** For source changes use `live_edit_open`, then `live_edit_read`, then `live_edit_save` with the returned `mtimeMs`. Report compile errors as shown by `live_edit_compile`. Open Artifacts for GUI SyncTeX and the document viewer. The submission tool accepts a directory for manuscript, blind, log, citation and Lean checks. Supply a new destination for arXiv or latexdiff output. Use `export_run_latex` for Overleaf. Locate offline citation and usage reports in the run using `read_run_text_artifact`.
- **Preferences, skills and compute.** Use Studio's saved research memories, preferences and skills when the user requests them. Open Settings for provider keys, backend paths, SSH credentials, the interactive SSH console or SCP. Inspect a registered host's built-in diagnostics only when relevant to the request.
- **Files.** Use absolute local paths for files passed to Studio. Honor the user's requested export location. Check `get_export_environment` for the local PDF or Drive defaults when relevant. Use `copy_run_pdf` for the pipeline's final PDF or `export_markdown_document` for PDF, DOCX and HTML. Choose a fresh filename. Use the Drive sync export when the user requests that destination.

For a tool that returns `jobId`, use `job_status` until the requested result is ready. A Studio job ID is different from a paper pipeline run ID. Studio job results have `state`, `events` and sometimes `result` or `error`. Paper pipeline progress and history are in `list_runs`. When a request's outcome is uncertain, look up the returned ID before retrying. Run a deletion or restore only for the specific target and effect requested by the user.
