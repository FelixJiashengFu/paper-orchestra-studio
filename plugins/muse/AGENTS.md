# PaperOrchestra Studio Plugin Rules

Follow these always-on guardrails whenever using the `paper-orchestra-studio` MCP server or any `po-*` skill:

1. **Strict Provenance Discipline**: Preserve `【原文】` (direct evidence with page/section/figure/equation), `【审读推导】` (your independent calculation, dimensional check, or reasoning), and `【不可核实】` (missing files, SI, code, or unreadable plots). Never invent DOIs, citations, statistical metrics, grant numbers, or experimental results.
2. **Protect Credentials & Validate Providers**: Never print, log, or request raw `.env` or `providers.json` API key values in chat responses. Use `po_check_environment`, `po_check_providers`, and `po_settings_and_setup` (`env_readiness`, `validate_providers_json`) to inspect readiness safely.
3. **Prefer Plugin MCP Tools & Conflict-Safe Edits**: Route project management, pipeline execution, data analysis, figure studio, literature library, LaTeX editing/SyncTeX, submission audits, SSH/GPU, and exports through `po_*` tools. Before `po_projects(update)`, fetch `updated_at` and pass `expected_updated_at`; before `po_latex_workbench(save)`, call `open`/`read` and pass `expected_mtime_ms` (keeping `.edit_backup/` original preservation); use `po_studio_bridge` when interacting with the Desktop Studio app window.
4. **Proactive Interactive UI**: Whenever the user wants to monitor runs live, intervene on pipeline stages via Canvas Console, circle-revise figure `bbox` regions visually, edit/compile LaTeX interactively, inspect the 10-group tool map, or asks for the Studio visual interface, launch `po_open_workbench` or `po_open_tool_tree`.
5. **Asynchronous Long Runs**: Paper generation (`po_start_paper_run`, `po_projects(resume_run)`) and multi-step analyses (`po_data_analysis`, `po_run_sop` with `async_mode=true`) execute in the background. Return the `job_id` / `run_dir` immediately and inspect progress cleanly via `po_job_manage` instead of blocking or guessing.
6. **Respect User Output Rules**: Never overwrite existing files unexpectedly (`copy_pdf` uses exclusive creation; `export_overleaf` requires explicit `allow_overwrite=true` to overwrite), and honor user-configured default output directories (`PO_DEFAULT_PDF_DIR`, `PO_DEFAULT_HTML_DIR`) or explicitly requested paths.
7. **Muse-Only Model Use**: This plugin runs the backend with `PO_HOST_AGENT=muse`. Every backend LLM step runs on the user's own signed-in Muse Code CLI and no other LLM API is called. Never ask for another provider's API key, leave model fields on `auto`, tell the user before starting a full paper run that it spends their Muse allowance, and write short pieces yourself in the conversation. See the `po-muse-host` skill.
